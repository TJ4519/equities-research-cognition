# Local workspace vertical V0

Status: implemented on the stacked branch. The vertical is mechanical and local. It is not analyst validation or a production release.

## Joined path

```text
workspace initialisation
-> mandate and prior perspective
-> original request and confirmed commission
-> exact local source capture
-> separate assertions for equal values
-> human-confirmed professional objects
-> purpose-specific evidence decisions
-> sealed assertion-level support context
-> direct child process
-> host-validated support relations
-> typed claims and content-addressed artifact
-> scoped use decision
-> attributed correction
-> human-confirmed scoped memory
-> second episode receiving that memory
-> retained evaluation case
-> deterministic replay
-> proof-pack export
```

The path keeps the broad analyst request separate from each bounded child action. It keeps source documents separate from assertions. It keeps result use separate from memory and method release.

## Micron relation

The hostile case stores two assertions with the value `37,378`.

The earnings-release assertion is rejected for the historical revenue object because the configured method requires the annual filing once available.

The annual-filing assertion is admitted for the historical revenue object.

The same earnings-release assertion is admitted for management-language comparison.

A support context contains the admitted assertion extract and a source receipt. It does not contain the full source document. The excluded assertion cannot enter the context through another passage in the same file.

A child result must state each assertion-to-professional-object support relation. The host rejects a citation outside the sealed context and a relation that was not admitted for the object and action.

## Local authority

The local kernel uses an append-only SQLite object and relation graph. Database triggers reject updates and deletions of canonical objects, relations, and blobs.

Source and artifact bytes use a content-addressed local store. Atomic writes and digest checks reject silent substitution.

The kernel represents:

- mandate;
- perspective version;
- episode;
- confirmed commission;
- source version;
- assertion;
- professional object;
- evidence-use decision;
- method;
- context;
- run;
- claim;
- result;
- artifact;
- decision;
- correction;
- memory;
- evaluation case; and
- replay.

Model-proposed professional meaning cannot authorise evidence use. Model-proposed memory cannot enter an active perspective. Mandate-authorised actors confirm commissions, professional meaning, evidence use, result use, corrections, and active memory.

## Context boundary

The context builder materialises:

- the exact confirmed commission;
- one method version;
- the exact prior perspective and authorised items;
- human-confirmed professional objects;
- admitted assertion extracts;
- source identity and blob receipts;
- scoped confirmed memory;
- included and excluded assertion populations; and
- a sealed manifest digest.

The child process receives no full source bytes in a support context. A later discovery or full-document reading context needs a separate action and authority.

Context integrity is verified before process start. Tampering with an assertion projection, source receipt, prior perspective, method, commission, object, memory entry, or manifest causes refusal.

## Runtime boundary

The direct adapter requires an absolute regular executable. It starts one child in the exact context directory with `shell=False`, a minimal environment, a new process session, a timeout, and an empty output directory.

The host preserves:

- argument array;
- working directory;
- process ID;
- process group;
- start and end times;
- exit code or signal;
- stdout;
- stderr;
- timeout state; and
- exact output population.

Run completion requires a successful process result and a valid `result.json`. A session manager reporting completion would not suffice.

The adapter does not provide operating-system filesystem isolation or network isolation. A child with ambient user permissions may still reach data outside the context. No strong firewall claim is permitted.

## Result and artifact custody

A result may contain typed claims, artifact declarations, and memory proposals.

Each claim must cite one or more assertion-to-professional-object relations present in the sealed context grant.

Each declared artifact must exist in the output population. Artifact bytes enter the content-addressed store. The original source and prior artifacts remain intact.

Run completion creates no professional authority. A separate scoped decision records use of an exact result or artifact.

## Correction and memory

A correction records the target, actor, reason, replacement, and scope without rewriting the original result.

A separate human-confirmed memory entry may promote the corrected meaning for a stated scope.

The hostile path creates a second episode from a new perspective containing the used result, decision, and confirmed memory. The second context receives the memory. Model-proposed memory is refused.

The V0 does not promote a correction into a reusable method.

## Replay

The replay engine walks backward through the stored object graph, verifies object, relation, blob, context, run, output, and artifact digests, and exports a proof pack.

A retained deterministic evaluation case reruns the exact command against a fresh copy of the sealed context. Replay compares the typed result and artifact digests.

The exact replay grade applies only to deterministic retained commands whose executable remains available.

Model-written research will need evidential re-derivation: an independent process should compare claims, support, contradiction, uncertainty, and scope rather than demand identical prose.

## Claims established

- Equal numerical values do not merge assertion identity.
- Evidence permission can differ by professional object, action, use, and time.
- An excluded assertion does not enter the sealed support context.
- A child cannot cite an assertion or assertion-to-object relation absent from its context grant.
- Context and blob tampering are detected.
- Run completion requires a known process result and valid output population.
- Result use, correction, active memory, and evaluation remain separate objects.
- A second episode can receive scoped confirmed memory.
- A retained deterministic method can be replayed exactly.

## Claims not established

- operating-system filesystem or network isolation;
- encryption at rest;
- lawful handling of licensed broker or expert-network material;
- useful frontier-model research;
- Codex or Claude Code integration;
- public-web discovery;
- a full-document discovery context;
- evidential replay of stochastic claims;
- workbook mutation or recalculation;
- analyst usefulness;
- reduced review burden;
- team synchronisation;
- production deployment; or
- commercial use of subscription-backed terminal agents.
