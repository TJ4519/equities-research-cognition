# Counterexample Register

Status: governing register of reproduced failures, rejected product forms, and propositions that the project must not silently revive.

A counterexample does not prove the final architecture. It removes an invalid shortcut and supplies a hostile test for the next build.

## CE-001 — Correct-looking value from an inadmissible source survives custody

**Observed mechanism**

The bound-job mechanical test creates a candidate for a consolidated GAAP revenue target with value `1,200` and source basis `earnings_release_nonfiling`. Exact job identity, input bytes, acknowledgement, output attestation, provisional authority, storage, restart retrieval, and rendering all succeed.

**Proposition falsified**

Exact bytes, a typed envelope, worker acknowledgement, and provisional custody do not establish source-to-target admissibility.

**Required hostile test**

For one exact target contract, a proposal using the wrong document class, entity, period, unit, accounting basis, or scope must be blocked before any candidate workbook or dependent calculation is created. A separate legitimate target must be able to permit a non-GAAP measure, derived value, estimate, or analyst assumption under its own policy.

**Status**

Reproduced mechanically in `test_synthetic_wrong_source_candidate_survives_as_provisional_only`. Semantic detection is missing.

## CE-002 — The Casebook exposes backend ontology as analyst work

**Observed mechanism**

The inherited `casebook.html` renders “Investment Casebook,” research-state transitions, claim ceilings, mechanisms, source changes, and runtime records as the primary product. It includes a forbidden eyebrow and asks the analyst to navigate terms produced for backend custody.

**Proposition falsified**

Making internal research state visible does not make a recognisable or useful analyst product. Richness cannot be created by exposing the ontology of the harness.

**Required hostile test**

A cold user should be able to identify the company, model line, proposed change, source, consequence, unresolved judgment, and resulting artifact without learning role names, state-machine vocabulary, or agent topology.

**Status**

Rejected product form. The underlying state and custody may be reused; the visible form must not govern the build.

## CE-003 — Spreadsheet review without spreadsheet execution

**Observed mechanism**

The prior spreadsheet review prototype displayed proposed changes and simulated review but did not open, patch, preserve, recalculate, or return an Excel workbook.

**Proposition falsified**

A spreadsheet-shaped review interface is not evidence of model updating. Showing a cell and an approval control does not prove that formulas, dependencies, or the native artifact changed correctly.

**Required hostile test**

The product must preserve the exact starting workbook, apply only an authorised operation to a stable target, run a supported recalculation engine, detect formula errors, record downstream changes, and return an exact candidate workbook. Unsupported work must refuse.

**Status**

Rejected as product proof. Native-workbook capability remains unimplemented.

## CE-004 — Manual Micron research attached after execution

**Observed mechanism**

A high-quality Micron research report exists outside the public product path. It was created manually by the coordinating agent rather than through login, canonical state, NTM/Codex execution, controlled failure, analyst action, and exact artifact lineage.

**Proposition falsified**

The quality of a report cannot establish that the product produced it. Attaching a report after the fact launders authorship and hides the execution path under test.

**Required hostile test**

Every visible material result in the demo must originate from exact product inputs and a real stored work order. The ordinary UI must retrieve it from canonical state after restart. No external report may be imported as the episode's success output.

**Status**

Forbidden shortcut. The manual report may be used only as an external quality reference with explicit provenance.

## CE-005 — Prompt and workbench prose mistaken for a host gate

**Observed mechanism**

The active protocols name source identity, exact passage, definition, scope, period, units, basis, bridge, residual, cutoff, and authority. The research-state validator checks field shape, dates, references, and selected invariants, but the source receipts and much of their semantic content are written by the worker. Comparable-State V0 explicitly ships no standalone validator.

**Proposition falsified**

Naming a distinction in a prompt or schema does not make it machine-owned, true, or enforced.

**Required hostile test**

A worker must be unable to create the source identity or target facts that validate its own proposal. The host must issue exact source, assertion, target, and policy identities and reject invented or mismatched references.

**Status**

Confirmed by code inspection. Prompt refinement is not the first corrective action.

## CE-006 — Captured correction mistaken for corrected artifact or learning

**Observed mechanism**

The blind-review application can record a free-text `CurrentCorrection`, a rubric or evaluation candidate, and an inactive future proposal. These records are not joined to an owned campaign artifact, workbook operation, dependency graph, recalculation, or scoped use disposition.

**Proposition falsified**

Recording expert feedback does not correct the current artifact, create an evaluation automatically, or prove cumulative improvement.

**Required hostile test**

A correction must bind the exact input, proposal, source or assumption, policy, artifact version, and human act. It must produce a new recalculated candidate or a refusal. A later workflow change remains quarantined until protected comparison and explicit promotion.

**Status**

Current correction custody exists; operational correction and governed learning do not.

## CE-007 — Uploaded-source label mistaken for a closed evidence boundary

**Observed mechanism**

The owned-job form asks for “Sources Codex may use,” while every generated Codex command includes `--search`. The host captures the uploaded files but does not record or constrain all external retrievals.

**Proposition falsified**

An input manifest does not prove that the model used only those inputs.

**Required hostile test**

For a closed-source work order, external search must be absent or technically denied where possible. Regardless of model exposure, no proposal may acquire authority unless it references a host-issued assertion from the exact captured source population.

**Status**

Confirmed by code inspection. The current system can prove declared inputs and supported artifact references, not complete information isolation.

## CE-008 — Campaign-wide correlation finality inside an evolving job

**Observed mechanism**

Once Langfuse trace links exist, artifact collection treats campaign custody as final. The research model otherwise supports further proposals and work orders.

**Proposition falsified**

A final trace join for one execution population cannot safely serve as finality for an indefinitely evolving analyst job.

**Required hostile test**

If the selected slice needs retries or later episodes, correlation and collection must become final per immutable episode, or later work must be deterministically blocked. The product must not admit a work order whose output can no longer be collected.

**Status**

Architecture inconsistency identified by code inspection. Not the first build unless the demo requires multiple agent episodes.

## CE-009 — Generic Agentic SDLC imported as product architecture

**Observed mechanism**

The donor harness organises software work through a closed intent taxonomy, recipes, a filesystem artifact bus, stage-specific roles, and a review fan-out. Much deterministic permission enforcement is deferred.

**Proposition falsified**

A coherent software-development harness does not establish the analyst's workflow, product vocabulary, evidence rules, or optimal agent topology.

**Required hostile test**

Any donor mechanism must solve a demonstrated repository problem under a reversible experiment. It must not replace PostgreSQL as canonical state, expose SDLC stages to analysts, or treat prompt-stated permissions as enforced controls.

**Status**

Rejected as organising product architecture. Reconstitution and run-record patterns remain eligible for a bounded engineering experiment.

## CE-010 — Numerically identical sources treated as interchangeable

**Observed mechanism**

Micron's FY2025 revenue is `37,378` million in both the earnings-release exhibit filed with the September 23, 2025 8-K and the 10-K filed October 3, 2025. The earnings-release financial statements are marked unaudited. A workbook target may nevertheless require the final annual report after it is available.

Official source records:

- 8-K accession `0000723125-25-000024`, filed 2025-09-23, EX-99.1 earnings release: `https://www.sec.gov/Archives/edgar/data/723125/000072312525000024/0000723125-25-000024-index.html`
- 10-K accession `0000723125-25-000028`, filed 2025-10-03, period ended 2025-08-28: `https://www.sec.gov/Archives/edgar/data/723125/000072312525000028/0000723125-25-000028-index.html`

**Proposition falsified**

Equal numeric values do not make source documents interchangeable for a particular model target.

**Required hostile test**

A versioned target contract for Micron FY2025 consolidated GAAP revenue in USD millions must block an EX-99.1/8-K assertion when configured to require the available 10-K, then accept the exact 10-K assertion. A different target contract may lawfully admit the earnings release.

**Status**

Selected public counterexample for the leading product hypothesis. No product run has yet reproduced and recovered from it.
