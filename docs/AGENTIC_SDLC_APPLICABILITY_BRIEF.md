# Separate investigation: Agentic SDLC as a donor mechanism

This investigation is deliberately downstream of repository and product
grounding. It must not define the analyst interface, the professional workflow
or the product centre.

## Why examine it

The public [Agentic SDLC repository](https://github.com/leobeeson/agentic-sdlc)
describes a Claude Code software-development harness in which durable artifacts,
declared role inputs and outputs, recipes, gates, run records and session
reconstitution coordinate work across stages. Its
[design summary](https://github.com/leobeeson/agentic-sdlc/blob/master/DESIGN.md)
also states that recipe guidance is semi-hard rather than deterministic and
that much permission and pre-tool enforcement is deferred in the starter.

Those patterns may stimulate useful thinking about decomposable research work,
debugging, compaction recovery, evaluations and controlled workflow changes.
They are not evidence that software-development stages map to sell-side work,
that analysts should see an artifact bus or agent roster, or that the starter's
controls satisfy research provenance.

## Entry gate

Do not begin this investigation until the PRO owner has completed and committed:

- `docs/pro/PRO_CONSTITUTION.md`;
- `docs/pro/REPOSITORY_GROUND.md`; and
- `docs/pro/PROMPT_AND_HARNESS_AUDIT.md`.

The PRO must be able to state the analyst job, causal product thesis, current
runtime path, authority split and evidence ceiling without reference to this
donor repository.

## Questions

1. Does its durable artifact bus offer a better way to make research work
   resumable and independently inspectable than the current job, artifact and
   work-order records?
2. Can declared semantic inputs and outputs improve the repository's work-unit
   contracts without turning flexible professional work into a brittle stage
   taxonomy?
3. Can initiative records, provenance headers and reconstitution reduce
   compaction drift while keeping canonical state in the product database?
4. Which gates are merely model instructions, which are executable procedures
   and which would require deterministic host enforcement?
5. Where would recipe-driven orchestration overfit one post-earnings episode or
   create unnecessary multi-agent work?
6. Could a per-task artifact double as a bounded worker instruction without
   allowing the worker to manufacture its own authority?
7. How would its review and reconciliation patterns interact with analyst
   judgment, target-specific source policy, protected evaluations and rollback?
8. What does the current NTM/Codex substrate already do better, and what would a
   migration cost or weaken?

## Required output

Write `docs/pro/AGENTIC_SDLC_APPLICABILITY_MEMO.md` with four sections:

1. **Retain:** mechanisms that directly solve a demonstrated project problem.
2. **Adapt:** useful patterns that need a research-specific or deterministic
   implementation.
3. **Reject:** vocabulary, topology or assumptions that would distort the
   product or duplicate stronger existing controls.
4. **Discriminating experiment:** the smallest reversible trial, its baseline,
   expected evidence, kill condition and rollback.

No finding in this memo changes the active product plan automatically. Any
adoption requires an explicit decision-ledger entry and a revised build
contract.
